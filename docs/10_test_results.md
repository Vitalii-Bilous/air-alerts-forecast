## 3. Перевірка гіпотез
1. **H1 підтверджено:** hgb проти `clim_28d` при H=3 +0.045, нижня межа ДІ +0.030 > 0.
2. **H2 підтверджено:** hgb проти `clim_7d` +0.048 [+0.032, +0.065]. Ризик сплесків не справдився: у найактивніший тиждень test (base rate 0.569, як у тиждень сплеску на validation) hgb усе одно кращий за `clim_7d` на +0.030 [+0.003, +0.061]. Пояснення не перевіряв. Імовірно, ріст у вересні був поступовішим, а модель уже бачила серпневий сплеск у train.
3. **H3 підтверджено:** при H=1 hgb кращий за обидва бейзлайни.
4. **H4 не підтверджено:** перевага hgb над logreg на test у межах шуму (H=3 +0.002 [−0.007, +0.012]). На validation вона була +0.019 [+0.007, +0.032]. Чесний висновок: бустинг і логістична регресія на test практично рівні; головний виграш дають ознаки, а не вибір моделі.

## 8. Як перевірити
1. `python run_eval.py --data data/volunteer_data_en.csv --final-test` → та сама таблиця (seed фіксований). Повторний запуск нічого не «підбирає»: він лише відтворює.
2. `python analysis/summarize_test.py` → парні порівняння, тижні, регіони.
3. **Leakage:** `[test] last start: 2026-10-09 20:56 UTC` < кінця test (2026-10-09 21:00 UTC), тобто дані після test відрізані. Найпізніший рядок train у кожному фолді: `t + H ≤ fold_start` (тест `test_fold_boundaries_and_purge`). У `results/test_chosen_params.csv` видно, що параметри обирались окремо в кожному фолді на внутрішньому спліті, без test-міток.
