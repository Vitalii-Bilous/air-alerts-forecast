# Крок 3б. Глибший аналіз validation і стратегія

Скрипт: `alerts_forecast/analysis/analyze_val.py`. Він бере `results/val_predictions.csv.gz`, донавчає бустинг без ознак по країні (ablation) і рахує зрізи. Працює ~3 хв, test не чіпає. Усі BSS нижче наведено з 95% ДІ (блочний bootstrap по добах). Основна модель тут — **hgb**.

## 1. Звідки береться виграш

**Моя гіпотеза про ознаки «по країні» була хибною.**

| | H=1 | H=3 |
|---|---|---|
| hgb проти hgb без ознак по країні | +0.005 [+0.002, +0.009] | +0.006 [−0.002, +0.014] |
| hgb без ознак по країні проти clim_7d | +0.036 [+0.028, +0.044] | +0.039 [+0.012, +0.064] |
| hgb проти clim_7d | +0.041 [+0.034, +0.048] | +0.045 [+0.018, +0.071] |

Майже весь виграш над бейзлайнами дає **регіональна** динаміка: стан «тривога активна», час від останнього старту, частота стартів за 1–168 год, 7- і 28-денні частоти разом. Ознаки по країні додають ~0.5%, і для H=3 це в межах шуму.

Додатковий факт: зріз «по країні за останні 3 год не було жодного старту» **порожній**. На validation такої години не трапилось ні разу, тож по всій країні фактично безперервно щось відбувається. Через це ознаки «по країні» мало розрізняють ситуації.

## 2. Стабільність по тижнях (H=3)

| Тиждень | Base rate | hgb проти clim_28d | hgb проти clim_7d |
|---|---|---|---|
| 08-15…08-22 | 0.410 | +0.040 [+0.018, +0.061] | +0.054 [+0.025, +0.077] |
| 08-22…08-29 | 0.462 | +0.030 [+0.004, +0.053] | +0.047 [+0.029, +0.067] |
| 08-29…09-05 | **0.566** | +0.124 [+0.102, +0.150] | **−0.013** [−0.069, +0.042] |
| 09-05…09-12 | 0.470 | +0.039 [+0.014, +0.064] | +0.087 [+0.031, +0.146] |

Модель стабільно краща за `clim_28d`, але **в тиждень сплеску активності (base rate 0.566) не обходить `clim_7d`**. Коротке вікно швидше «наздоганяє» різкий ріст, ніж модель, навчена на минулих місяцях. Для H=1 модель краща за обидва бейзлайни в усіх 4 тижнях.

## 3. Ситуації

| Зріз | H | Частка рядків | Base rate | hgb проти clim_7d |
|---|---|---|---|---|
| тривога в регіоні активна в t | 1 | 26% | 0.147 | **+0.097** [+0.071, +0.124] |
| у регіоні тихо в t | 1 | 74% | 0.256 | +0.025 [+0.016, +0.035] |
| тривога активна | 3 | 26% | 0.415 | +0.051 [+0.026, +0.076] |
| тихо | 3 | 74% | 0.499 | +0.042 [+0.007, +0.074] |
| за 24 год у регіоні не було стартів | 3 | 20% | 0.057 | +0.049 [−0.016, +0.126] |

Найбільше модель вчиться на тому, що **поки тривога триває, новий старт протягом години менш імовірний** (0.147 проти 0.256). Це прямий наслідок того, що потік тривог послідовний, і бейзлайни цього не бачать. Передбачити першу тривогу після тихої доби модель майже не вміє: ДІ перетинає 0.

## 4. Регіони (H=3, hgb проти clim_7d)

- **Найкраще:** Тернопільська +0.106, Київська +0.094, Донецька +0.093, Житомирська +0.068.
- **Гірше або на рівні:** Івано-Франківська −0.018 (base rate 0.013, тривог майже немає), Одеська −0.004, Кіровоградська +0.010, Черкаська +0.011.
- Таблиця для всіх регіонів: `results/val_region_hgb.csv`. На рівні регіону 4 тижні дають великі ДІ, тож дрібні різниці не тлумачу.

## 5. Висновки

1. Модель **корисна, але скромно**: 4–6% Brier над найкращим бейзлайном. Виграш найбільший у «механіці» послідовного потоку тривог, а не в передбаченні нових хвиль.
2. Найбільший ризик для test — **дрейф і сплески**. На тижні сплеску модель не краща за `clim_7d`, а у вересні активність, судячи з помісячних агрегатів, які я бачив на кроці 1б, різко зросла. Тому на test перевага над `clim_7d` може зменшитись або зникнути. Це варто прямо написати в README **до** відкриття test.
3. Ознаки по країні майже нічого не дають. Прибирати їх зараз я **не раджу**: це було б ще одне рішення, підібране на validation. Модель лишаємо такою, як оголосили.
